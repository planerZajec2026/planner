# Next specs: plan (10–12)

Short outlines of the specs that follow 08 and 09. Each will get a full spec before work starts. They are listed here so 08 and 09 can refer to them, and so the order is clear.

## 10: Odczyt danych z Supabase
- Switch `src/lib/data/*` from mock data to Supabase, using the typed server client from spec 08. The function signatures stay the same, so the components don't change.
- Map snake_case rows to the camelCase domain types, e.g. `godzina_od` → `od`, `przedmioty` join → `przedmioty: string[]`.
- Timetables fetch only the selected week, and apply `dni_wolne` and `odwolane_zajecia`.
- The sidebar footer reads `ustawienia`.
- Decide what to cache (`use cache` with `cacheTag`) and what stays per request.
- Delete `src/lib/mock-data.ts`.
- E2e runs against the local Supabase stack with the seed from spec 08. The expected values from spec 06 still hold.

## 11: Logowanie, role i zapis
- Supabase Auth with e-mail login. Add a `profile` table with a role (`planista` may edit; everyone else reads).
- RLS write policies for `planista`.
- Server Actions replace the local-only saves:
  - adding an instructor (with the photo uploaded to Storage);
  - adding a class by hand;
  - the JSON import, as one transaction (an RPC);
  - the "Pomiń"/"Zastąp" choices applied.
- The exclusion-constraint names from spec 08 map to the existing Polish conflict messages.
- Add a `planner-staging` project for Preview deployments (spec 09) before this ships.
- Open decision: who creates accounts, and whether viewing requires login.

## 12: Eksport do Excela
- A route handler generates `.xlsx` (e.g. with `exceljs`) for:
  - a group's week;
  - an instructor's week;
  - the scopes in the export panel (whole plan, programme, group, instructor).
- The disabled export buttons are enabled and download the file.
